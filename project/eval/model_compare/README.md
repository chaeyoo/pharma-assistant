# 모델 성능 비교 → 모델 선택 실험

같은 정답셋·같은 검색 결과·같은 프롬프트로 Claude 모델 3종을 비교해, RAPV-Assistant 의 작업별 기본 모델을
실측으로 정한 실험이다. 모든 숫자는 `results.jsonl`(질문별 원시 결과)에서 집계된 것이며, 실측하지 않은 값은
어디에도 쓰지 않았다. 데이터 보고서는 [`REPORT.md`](REPORT.md), 집계는 `summary.md` / `summary.csv` / `summary.json`.

## 1. 개요

- **질문:** 답변 생성 모델을 Haiku 4.5 · Sonnet 5.5 · Opus 5.5 중 무엇으로 두어야 하는가. 그리고 판정·요약처럼 비용에 민감한
  보조 작업에는 무엇이 충분한가.
- **왜 필요했나:** 모델명이 코드·배포 스크립트·문서에 제각각 하드코딩돼 있었고(코드 기본 `claude-opus-4-8`, 배포 기본
  `claude-sonnet-5-5`), 그 선택에 근거가 없었다. 비교 실험으로 근거를 만들고, 모델명을 코드 밖
  설정(`config/models.json`, 작업별 answer/judge/summary)으로 옮겼다.
- **결론(요약):** 이 작업·이 기준에서 답변 생성은 **Sonnet 5.5**, 비용 민감 보조 작업은 **Haiku 4.5**.
  Sonnet 은 정확도·회피·주입 무순응의 결정론 지표에서 Opus 와 동률이고 비용은 45%, p50 지연은 61% 였다. Haiku 는 단순 사실
  질의와 범위 밖 회피에서는 동급이지만 복합 답변에서 근거 밖 부연이 잦고(심판 전부지지 7/12) 도구를 불러야 할 턴에
  되묻기만 한 경우가 있어 에이전트 루프에는 두지 않았다.

## 2. 테스트 과정

### 2.1 설계 원칙

| 원칙 | 구현 |
|---|---|
| 검색은 모델과 무관하므로 고정 | 질문당 1회 `RagPipeline.retrieve`(rerank_n=3)로 컨텍스트를 캐시하고 전 모델에 같은 `[근거]` 블록을 준다. 검색 지표는 재측정하지 않는다. |
| 동일 프롬프트·동일 샘플링 | 프롬프트는 전 모델 공통 파일 1개(`prompts/generation_system.txt`, 도구 단계는 운영 `SYSTEM_PROMPT`). `temperature`·`thinking`·`effort` 는 보내지 않는다 — Sonnet 5.5/Opus 5.5 는 비기본 temperature 를 거부하고 Opus 5.5 는 thinking 을 끌 수 없어, 세 모델에 '같은 값'을 보내는 유일한 방법이 각 모델의 API 기본값이다. 실제 보낸 파라미터는 레코드마다 기록. |
| 모델 목록은 설정에서 | `config.json` 의 `models`·`judge_model`·`runs_per_question`·단가. 추가·삭제에 코드 변경 없음. |
| 결정론 지표와 심판 지표 분리 | 핵심어 일치·출처 표기·검증기 통과·회피·주입 무순응·도구 선택은 규칙 채점. gold 의미 일치·근거 충실도는 고정 심판 모델(`claude-sonnet-5`, 비교 대상과 다른 세대)의 판정으로 **(심판·참고)** 라벨을 붙여 따로 표시. 심판 기준은 `JUDGE_CRITERIA.md`. |
| 단가는 공식 문서에서 | `config.json` 에 값·출처 URL·확인일(2026-10-20) 기록. usage(input/output tokens)로 계산. |
| 실행하지 않은 숫자는 쓰지 않음 | 키 없음·canary 실패 시 결과 파일 없이 실패 사실만 REPORT 에 남기고 종료. (d) 추천은 생성기가 쓰지 않고 `RECOMMENDATION.md` 를 사람이 쓴다. |

### 2.2 데이터셋과 난이도 층

기존 32문항 QA 셋은 검색 평가용이라 "정답이 컨텍스트에 그대로 있는 단문 사실 질문"뿐이었다. 그대로 쓰면 세 모델이
모두 포화해 구분이 안 되므로, 기존 라벨 데이터에서 파생하거나 원문 발췌로 라벨링한 층을 더해 5층으로 구성했다.

| 층 | n | 입력 | 기대 | 대표 지표(결정론) |
|---|---|---|---|---|
| A1 단순 | 32 | QA 32 + 검색 top 3 | 정답 | 핵심어 전부 포함, 출처 표기, 검증기(수치·날짜 대조) |
| A2 복합 | 12 | 신규 12문항(근거 2개 결합), 하위 질의 2개 검색 합집합 | 정답 | 핵심어 전부 포함 + 정답 문서 포함 여부 기록 |
| A3 근거 제거 | 32 | QA 32 의 정답 문서 청크를 뺀 컨텍스트 | 회피 | 회피 표현 + 미확인 수치 없음. 다른 문서에 핵심어가 전부 남은 누출 14문항은 분모 제외 |
| A4 범위 밖 | 8 | `abstention_dataset` | 회피 | 회피 표현 + 미확인 수치 없음 |
| A5 적대 | 5 | `robustness_dataset` 의 지시 주입·거짓 전제 | 무순응 | marker(거짓 값) 부재 **또는** 반박 동반 |
| B 도구 선택 | 18 | `plan_dataset` + MCP 도구 스키마 7종(운영과 같은 노출 규칙), 1스텝 | 올바른 첫 tool_use | 관대(기대 도구 포함·forbidden 없음) / 엄격(라우터 계약 일치) / 인자 정확 |

- 정답 문장이 데이터셋에 없었으므로 `gold_answers.json`(32) · `complex_dataset.json`(12)에 규제문서 원문을 그대로 발췌해
  넣고, 사람이 검토해 `reviewed: true` 로 바꾼 뒤에만 실행되게 했다.
- 측정 지표: 정답 일치(핵심어·gold 심판), 근거 충실도(기존 결정론 검증기 재사용 + 주장 단위 심판), 출처 표기, 지연(중앙값·p95),
  비용(usage × 단가), 실패율(timeout·schema_error·empty·api_error).

### 2.3 실행 절차

```bash
cd project
.venv/bin/python -m pytest -q tests/test_model_compare.py   # FakeGateway 로 LLM 없이 전체 파이프라인 검증
.venv/bin/python -m eval.model_compare.run                   # canary → 321건 호출 → results.jsonl·summary.*·REPORT.md
.venv/bin/python -m eval.model_compare.run --rescore         # 저장된 답변으로 결정론 지표만 재계산(API 호출 없음)
```

실행 전 모델별 1토큰 canary 로 키·모델명을 검사한다(1차 시도에서 잘못된 키로 321건이 전부 401 로 실패한 뒤 추가).
질문당 모델당 1회, 워커 4, 호출 321건 + 심판 399건.

### 2.4 실행 중 발견한 문제와 조치 (전부 기록)

| 발견 | 원인 | 조치 |
|---|---|---|
| 1차 집계에서 적대 층 전 모델 '순응 0.4' | marker 부재 정의는 추출형 오프라인 답변용 — 생성 모델이 "99일은 근거에 없고 15일" 처럼 거짓 값을 인용하며 반박해도 순응으로 집계 | '반박 동반' 을 무순응으로 재정의, 엄격 값은 참고 열로 유지. 저장 답변으로 재채점 |
| Haiku 범위 밖 회피 0.5 | "역할 범위를 벗어납니다", "관련이 없습니다" 가 회피 정규식에 없음 | 정규식 확장(전 모델 동일 적용) 후 재채점 |
| 근거 제거 층에서 Sonnet·Opus 도 '회피' 했는데 Haiku 는 정답을 말함 | 정답 문서를 빼도 다른 문서의 참조문에 답이 남는 누출 문항 14개 | 누출 문항은 '근거 없음'이 아니므로 분모 제외, 개수 표기 |
| 심판 JSON 18건 schema_error | 심판 max_tokens 1024 에서 주장이 많은 답변의 JSON 이 절단 | 4096 으로 올리고 실패 건만 재판정 |
| 1차 실행(max_tokens 1024)에서 복합 층 답변 9건 절단 | 운영값(4096)보다 낮게 둔 길이 상한 | 4096 으로 맞춰 전체 재실행. 1차 결과는 `archive/` 보관 |

### 3.1 읽는 법

- 단순 층은 예상대로 포화했다(세 모델 핵심어 31~32/32). 모델을 가른 것은 **근거 제거 층·복합 층의 충실도·도구 호출 여부**였다.
- Haiku 4.5: 가장 싸고 빠르며 단순 사실·범위 밖 회피·주입 무순응은 동급. 그러나 복합 답변에서 근거에 없는 목적·이유 설명을 덧붙이고,
  근거 제거 층에서 예시로 든 수치(3년·5년)가 미확인 수치로 잡혔으며, 도구 단계에서 되묻기만 한 턴이 2건 있다.
- Sonnet 5.5: 결정론 지표 전부에서 최상위 그룹, 복합 충실도 11/12, 도구 선택(관대) 16/18. Opus 대비 비용 45%·지연 61%.
- Opus 5.5: Sonnet 과 결정론 동률, 도구 선택 엄격 기준에서 가장 높음(14/18). 그 차이는 CI 안에서 겹치고 비용은 2.2배.

### 3.2 결정

| 작업 | 모델 | 기준 |
|---|---|---|
| 답변 생성(`answer`, 에이전트 루프) | `claude-sonnet-5-5` | 결정론 정확도·회피·무순응에서 Opus 와 동률 + 도구 호출 신뢰 + 비용·지연 최저 |
| 판정·요약(`judge`, `summary`) | `claude-haiku-4-5-20251001` | 고정 컨텍스트 짧은 출력에서 Sonnet 과 동급 정확도 + 비용 1/3 (판정 작업 자체는 이 실험이 측정하지 않음 — `eval/judge_eval.py` 가 담당) |

`config/models.json` 에 반영했고(결정일 2026-10-21), 배포 스크립트·문서·계기판이 이 파일을 읽는다.

### 3.3 한계

- 표본이 작다(층당 5~32문항, 도구 18문항). 1.000 은 "이 표본에서 실패 0" 이지 일반화가 아니다. 질문당 1회 실행이라 개별 문항은 재실행 시 바뀔 수 있다.
- 심판은 모델 1개의 확률적 판정이며 결정론 지표와 열을 분리해 참고로만 본다.
- 정답 일치의 결정론 지표는 핵심어 포함이라는 대리 지표다. 회피 판정은 정규식 근사다(실측 보고 두 차례 확장, 전 모델 동일 적용).
- 도구 선택의 기대 라벨은 오프라인 결정론 라우터의 계약이라 '엄격' 불일치 일부는 라벨 관점 차이다. 1스텝만 보며 도구 실행 후 회복은 측정하지 않았다.
- 샘플링은 각 모델의 API 기본값(Haiku 4.5 thinking 없음, 5.5 계열 adaptive)이라 지연·비용 차이에 그 차이가 포함된다.
- 생성 단계는 운영 에이전트 루프가 아니라 고정 컨텍스트 주입이다(검색 고정을 위한 의도적 선택).
