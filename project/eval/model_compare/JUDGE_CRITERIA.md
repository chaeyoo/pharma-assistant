# 심판(judge) 프롬프트와 판정 기준

비교 실험의 심판 지표 2종은 **비교 대상과 다른 고정 모델 1개**(`config.json` 의 `judge_model`)가
판정한다. 심판 판정은 확률적이므로 보고서·집계표에서 항상 **"(심판·참고)"** 로 표시하고,
핵심어 일치·출처 표기·검증기 통과·도구 선택 같은 **결정론 지표와 열을 분리**한다.

| 지표 | 프롬프트 파일 | 입력 | 출력 계약 | 집계 |
|---|---|---|---|---|
| 근거 충실도 (faithfulness) | `prompts/judge_faithfulness.txt` | [근거] = 생성 단계에 준 것과 **동일한** 컨텍스트 블록, [답변] = 모델 답변 | `{"claims":[{"claim","supported","reason"}]}` | 주장 전부 지지 비율(문항 단위) · 주장 단위 지지율 |
| 정답 일치 (correctness, 심판) | `prompts/judge_correctness.txt` | [질문], [기대 답] = `gold_answers.json` 의 원문 발췌, [모델 답변] | `{"match": bool, "reason"}` | 일치 비율(문항 단위) |

## 판정 기준 요약

**충실도** — "참인가"가 아니라 "주어진 근거에 있는가"를 본다.
- 주장(claim)은 참/거짓을 가릴 수 있는 최소 사실 진술. 출처 표기·메타 발화는 주장이 아니다.
- `supported=true`: 근거에 명시돼 있거나 의미를 바꾸지 않은 재서술·요약.
- `supported=false`: 근거에 없는 수치·기한·대상·조건, 의미(긍정/부정·주체·방향) 변경, 근거가 말하지 않은 단정.
- 세계 지식으로 참이어도 근거에 없으면 false. 올바른 회피("근거에서 확인되지 않음")는 claims 빈 배열.
- 불확실하면 false 로 몰지 않는다(오탐 억제 — 운영 judge 와 같은 규율).

**정답 일치** — 기준은 오직 [기대 답].
- `match=true`: 질문이 묻는 핵심 사실(수치·기한·대상·구분·절차)이 일치. 표현·순서·부가 설명 차이는 무관.
- `match=false`: 핵심 사실이 다르거나 빠졌거나, 기대 답이 명확한데 모델이 회피.

## 출력 처리 규칙(코드, `scoring.py`)

- JSON 은 코드펜스·전후 텍스트를 흡수해 추출한다(`src/verify/llm_judge._extract_json` 재사용).
- 계약 위반(필드 누락·타입 불일치)은 **판정 없음(None)** 으로 두고 집계 분모에서 제외한다 —
  절반만 파싱된 판정을 '통과'로 위장하지 않는다. 레코드의 `judge_status` 에 `schema_error` 로 남긴다.
- 심판 호출 실패(API 오류)는 `judge_status=unavailable` 로 기록한다.

## 왜 기존 환각 검증 계층을 그대로 쓰지 않았나

운영 중인 LLM judge(`src/verify/llm_judge.py`)는 부정문 뒤집기·주어 교체·의미 반전 **3종만**
판정하는 2차 검증기라 "답변의 각 주장이 컨텍스트에 있는가"를 묻지 않는다. 대신 운영의
**결정론 게이트**(`src/verify/verifier.verify_answer`: 수치·날짜·방향어 대조)는 그대로 재사용해
`verifier_ok` 열로 보고한다. 충실도 심판은 이 결정론 게이트가 못 보는 비수치 주장을 보완한다.
